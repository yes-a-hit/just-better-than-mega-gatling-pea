# 安装与部署

目标是 **PvZ2 Gardendless 0.15.0 + GP-Next 1.5.0-pre.1**。

## 一、开启 JavaScript 模组

当前 GP-Next 版本只允许从开发者控制台开启 JS 模组，设置页里没有开关。

1. 进入游戏，按 `F12` 打开开发者工具
2. 切到 **Console**
3. 执行：

   ```js
   await gpNext.mods.enableJsModding()
   ```

4. 按提示应用或重启

> 纯 JSON 模组不需要这一步；本模组带 `scripts/main.js`，需要。

## 二、导入

两种方式，任选其一：

**ZIP（推荐给玩家）**

1. 拿到 `dist/just-better-than-mega-gatling-<version>.zip`（由 `tools/pack.ps1` 生成）
2. GP-Next 侧栏 → **模组** → **导入 ZIP**
3. 核对名称与版本后安装

**文件夹（推荐给开发）**

1. 把仓库克隆或复制到本机
2. GP-Next 侧栏 → **模组** → **导入文件夹**
3. 选择包含 `pack.json` 的那一层——本仓库的**根目录**就是

> 仓库根同时是模组根，所以 `git clone` 之后可以直接导入，不需要额外构建。

## 三、启用（最容易漏的一步）

导入后的条目 `enabled` 默认是 `false`：

1. 在模组列表里**勾选**本模组
2. 点 **保存并应用**

**不勾选等于没装**——包在 `installed/` 里、配置里也有，
但 JS 一行不跑、数值补丁一条不生效。排查时先看 `configuration-state.json`
的 `enabled` 字段，别急着翻日志。

## 四、重启并验证

1. 点 **保存并应用**，看到提示后**完全退出游戏**（不是回主菜单）
2. 重新启动，进入任意关卡
3. 打开 GP-Next → **模组** → 点本模组名称，确认详情面板里各挂载点都有值

**不需要任何额外脚本、命令行或补丁工具。**

> 少数 GP-Next 构建在「保存并应用」后重启会停在
> `启动已停止（afterProject）。Native build identity is unavailable`。
> 那是该构建拿不到 `Native build identity`、导致配置应用环节失败，
> **导入任何模组都可能触发，与本模组无关**。处理方式见第八节「已知问题」。

## 五、更新

重新导入新 ZIP 即可。`uuid` 不变，会被识别成同一个模组的新版本。

**不要直接改 `installed\<hash>\` 里的文件**——会触发

```
Package digest does not match stored bytes
```

安装目录名就是包内容摘要（算法未公开，对单文件哈希、路径+内容拼接都不匹配）。
改包必须重新导入，让 GP-Next 重算。

## 六、停用 / 回滚

- 取消勾选 → 保存并应用。带资源的内容模组通常需要重启。
- 不要在战斗中强行切换。
- 若存档仍引用模组内容，按提示恢复所需模组。
- 配置坏了走**恢复配置界面**，不要反复清空存档。

## 七、数据目录

| 项 | 位置 |
|---|---|
| 数据目录 | `%APPDATA%\com.pvzge.game\gp-next\` |
| 配置状态（唯一权威） | 上述目录下 `configuration-state.json` |
| 已安装包 | `gp-next\installed\<sha256>\` |
| 存档备份 | `gp-next\save-backups\native-player\` |

游戏内 **模组 → 打开目录** 可直接跳转；以游戏实际打开的位置为准。

## 八、排查

模组详情面板里有完整状态：

- **大哥 BGM**：资源字节数、是否接管、当前判定、存活数、游戏阶段、音乐音量标量、播 / 停次数
- **元素豌豆**：挂载点、累计发射、六种弹的实测分布
- **融合大哥**：六个挂载点的状态与实测计数

点「输出诊断到日志」把每一步结果写进 GP-Next 的**日志**页。

| 现象 | 先看哪里 |
|---|---|
| 完全没反应 | 模组列表里勾没勾；`configuration-state.json` 的 `enabled` |
| 数值没变 | `PlantProps` 补丁生效需要重启；JS 钩子只影响运行时新建 / 更新的实例 |
| 「接管状态」一直未接管 | 面板里的「游戏阶段」，只有 `running` / `paused` 才接管 |
| BGM 出不来 | 面板「资源」行。若为 `readBytes 返回空`，说明打包漏了 `audio/` |
| 原 BGM 没静音 | 面板「音乐音量标量」，接管时应为 `0.00`；始终 `1.00` 说明拿不到 `MusicController` |
| 应用后打不开 | 见下方「已知问题」 |

### 已知问题：重启后停在「启动已停止（afterProject）」

```
启动已停止（afterProject）。Native build identity is unavailable
```

**原因**：部分 GP-Next 构建拿不到 `Native build identity`，导致「保存并应用」时
把 `desired` 落到 `active` 的那一步失败；失败之后配置状态不追平，
于是每次启动都撞同一个错。**导入任何模组都可能触发，与本模组无关。**

**处理**：按提示进入**恢复配置界面**，选择返回上次可用的配置，
游戏即可正常启动，存档不受影响。

- 不要反复清空存档——那解决不了这个问题，只会让进度白丢。
- 如果每次装模组都出现，说明该 GP-Next 构建本身不支持动态应用模组配置，
  可以尝试更新到较新的 GP-Next 版本后再安装。

### 其它

- 模组面板里点「输出诊断到日志」，会把每一步定位结果写进 GP-Next 的**日志**页，
  报错时把它一并附上即可。
- 游戏版本升级后若出现异常，先到 GP-Next 的 **数据** 页重新导出一次，
  比对字段有没有变化。
